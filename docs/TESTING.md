# 测试与真实样本验证

## 一条完整质量门禁

本地和 CI 使用同一个命令：

```bash
npm run check
```

它依次检查格式、运行全部 Vitest 测试，并完成 TypeScript 检查与生产构建。修复某个模块时可以先跑定向测试，例如：

```bash
npm test -- tests/sample-pdf.test.ts
```

## 四层验证

1. **纯函数单测**：版面切分、表格、文字清理、页码范围、OCR 坐标等直接构造输入，运行快，负责阻止算法回归。
2. **入库 PDF 夹具**：`tests/fixtures/` 覆盖单栏、双栏、有线表格、图片、页眉页脚和可搜索扫描件。生成方式与限制见该目录的 README。
3. **真实浏览器回归**：用 Playwright 或手工打开开发/预览站，实际选择文件，确认队列、进度、取消、下载、工具切换、移动端布局和浏览器控制台。
4. **私有真实语料**：只在本机使用用户授权的目录，覆盖更多文件来源、体积和版式。原文件、文件名、提取文本、转换结果和截图均不得提交。

单元测试通过不代表输出版式正确。PDF、DOCX 或页面样式有变化时，必须额外做视觉检查。

文档安全和取消的合成浏览器回归已放在 `tests/browser/document-safety.js`。启动 Vite 开发站后，用已有的 `playwright-cli` 打开该站，再执行：

```bash
playwright-cli run-code --filename tests/browser/document-safety.js
```

使用命名浏览器会话时，命令带上相同的 `-s=会话名`。脚本检查远程图片、srcset、CSS、iframe、页面跳转、合并单元格、罕见字符占位，以及解码等待取消后的后续转换和 iframe 清理。它不需要新增测试框架或私有样本。

## 浏览器回归矩阵

每次发布至少检查：

| 路径 | 必查内容 |
| --- | --- |
| PDF → Word | 原生文字、表格、图片、重复页眉页脚、转换报告 |
| PDF → Markdown | 文本顺序、图片 zip、manifest、报告 |
| PDF → 图片 | 页码范围、PNG/JPEG、多页 zip |
| Word → PDF | 标题、段落、表格、图片、分页 |
| Markdown → PDF | GFM 表格、任务项、代码块、内联编辑器 |
| 图片 → PDF | 多图排序、旋转、纸张与边距、下载 |
| 反馈入口 | 失败任务卡的「反馈这个问题」、报告底部的「结果不对？去反馈」打开的 Issue 表单已预填环境和诊断信息，且不含文件名 |
| 工具页直达 | 直接打开 `/word-to-pdf` 等地址时标题、描述是该工具的；不存在的地址返回 404 状态但页面仍能用 |

桌面至少覆盖 1440×900，移动端至少覆盖 390×844；两者都检查横向溢出、键盘焦点和控制台错误。生产部署后再对正式域名重复一遍轻量冒烟测试。

## 示例 PDF 的发布约束

`public/samples/demo.pdf` 是四种界面语言共用的中立示例，因此正文保持全英文。它由 `scripts/make-demo-pdf.py` 生成，必须同时满足：

- A4、两页、没有加密或脚本；
- 使用内置 Latin 字体，不依赖 CJK 字体下载；
- 覆盖标题、段落、列表、有线表格、合并单元格、位图、重复页眉页脚和页码；
- `tests/sample-pdf.test.ts` 通过；
- 用 Poppler 渲染全部页面后，没有裁切、重叠、黑块或不可读文字。

## 私有样本纪律

- 先做只读盘点，再按格式、页数、体积、文字层和图片特征分层抽样。
- 不把私有文件复制到项目目录；浏览器转换产生的下载放在忽略的 `tmp/` 或 `output/`。
- 文档只记录总数、格式分布、通过/失败数量和匿名化问题类型。
- 发现问题时，优先制作最小的合成夹具；不能安全脱敏的问题只记录现象，不提交原文。

## 2026-09-02 真实语料回归

本轮语料来自用户明确授权的本机 2026-04 文件目录。只记录聚合结果，不记录目录、私有文件名或内容。

### 全量只读盘点

- 共 563 个文件、2,032,403,091 bytes；其中 391 个属于应用支持的输入格式。
- 支持格式分布：PDF 341、DOCX 41、Markdown 7、PNG/JPEG 2。
- 391 个候选都能完成基础结构读取；PDF 共 6,729 页，其中 1 份加密、100 份抽样页接近扫描/图片型、2 份含旋转页。

### 真实浏览器转换

| 流程 | 样本 | 结果 |
| --- | ---: | --- |
| PDF → Word | 6 | 6 成功 |
| PDF → Markdown | 3 | 3 成功 |
| PDF → 图片 | 3 | 3 成功 |
| Word → PDF | 8 | 8 成功 |
| Markdown → PDF | 7（目录内全部） | 7 成功 |
| 图片 → PDF | 2（目录内全部，合成一份） | 2 页 PDF 成功 |
| 加密 PDF | 1 | 正确提示输入密码，未把预期状态记作转换失败 |

12 份普通 PDF 按体积、页数、原生文字、扫描/图片、矢量线条、旋转页和中英文字层分层选择，范围为 1-25 页、约 79 KB-8.0 MB。8 份 DOCX 覆盖约 6 KB-3.9 MB、无表格到 87 个表格节点、纯文字到 17 个媒体资源。

额外抽查了实际下载产物：两份 DOCX 均为有效 ZIP/OOXML 包；三份 PDF 分别为 4、2、14 页，均可被 Poppler 重新打开并渲染。图片流程实际执行了重排、旋转、A4 和普通边距设置，第二页方向与页序符合操作结果。示例 PDF 也通过页面按钮完成了 PDF → Word 转换。

### 观察

- 两份真实 PDF 触发了 pdf.js 对非标准 TrueType 指令或损坏文字层的非致命警告，所有任务仍完成且没有界面错误。后续若出现内容缺失，应先把该版式提炼为脱敏夹具，再决定是否修改解析层。
- 一份包含特殊字体/分散对齐的 DOCX 在浏览器排版后出现较宽的中文字距，但内容、链接、颜色和分页均可读。这属于当前“可编辑/可搜索优先，而非像素级复刻”的明确质量边界。
