# 图片压缩、格式转换与尺寸调整

目标：在不新增依赖、不上传文件的前提下，增加三个图片工具（压缩 / 转格式 / 改尺寸），并修复图片转 PDF 的 SVG 问题。

## 方案

1. 入口：导航新增第三组「图片工具」，三个地址 `/compress-images`、`/convert-images`、`/resize-images` 共用一个组件，
   只换默认设置（压缩保持格式、转换默认 JPG、改尺寸默认长边 1920）和设置项顺序；各自记住设置。
2. 流水线：`core/image/compress.ts` 在单独的图片 Worker 里逐张处理，三个工具共用一个 Worker；取消即 terminate。
3. 格式：原格式 / JPG / PNG / WebP（浏览器能编码才显示）；写不回去的格式按透明和内容改存 PNG 或 JPG。
4. 透明：PNG / WebP 默认保留；JPG 或选了「填充」时铺所选底色，先铺底再编码，避免透明变黑。
5. 压缩：JPG / WebP 用质量档；PNG 自写编码器（选颜色类型、逐行滤波、fflate 9 级），标准档减到 256 色、小体积 64 色；
   按目标大小时二分质量（PNG 依次试颜色数），不够再按体积比例等比缩小。
6. 尺寸：长边 / 宽 / 高 / 百分比等比、只缩不放；精确尺寸分居中裁切和完整放入；SVG 在主线程按最终尺寸栅格化，可放大。
7. 不变大：没要求改格式、尺寸、背景时，结果不更小就给原图；转换和改尺寸遇到已符合设置的图原样保留。
8. 输入：多选、拖放、粘贴、拖入或选择文件夹（相对路径进 zip）；动图在读文件头时就标跳过，HEIC 等解不了的给出原因。
9. 输出：单张直接下载，多张打成保留目录结构的 zip；对比对话框可拖动分隔线、看实际像素。
10. 手机：从图片工具进入不再整页拦截，单张按约 1600 万像素上限处理。

## 验证

纯函数单测覆盖文件头识别、尺寸规则、格式决策、目标大小搜索、PNG 编码（测试里自带解码器逐像素核对）、减色和 DPI；
`tests/browser/image-tools.js` 在开发站覆盖流水线和界面主流程；桌面 1440×900、手机 390×844，浅色 / 深色、四种语言人工过一遍；
生产构建后在预览站确认 Worker 打包正常。
