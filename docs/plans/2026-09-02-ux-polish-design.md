# Local PDF 0.5.0 体验优化设计

## 方向

本轮延续现有“暖纸、墨色、赭橙”的本地工具气质，不重做品牌视觉，也不引入新框架。重点是让六个工具更像一个连贯的工作台：用户切换页面后，仍能看见其他工具里保留的任务或图片；深链和站内导航始终有正确的页面标题与 canonical；上传、编辑、生成、下载之间的状态变化清楚但不过度打扰。

## 交互与组件

工具导航为每个有内容的工具显示计数徽标，运行中的徽标使用主色并带克制的脉冲；计数也写入链接的无障碍名称。上传区改成一个真正的文件选择按钮，示例入口是并列的独立按钮，避免一个“按钮”里再嵌套另一个按钮。六个常驻工具的高级设置面板使用各自唯一的 `id`，确保 `aria-controls` 始终准确。

Markdown 编辑器打开后，文件投放区收成一行，把首屏空间让给正文；编辑器增加标题与收起动作，提交后自动收起但保留草稿，便于查看结果后继续修改。移动端不改变信息结构，只扩大图片排序、旋转、删除和批量操作的触控面积，并保持两列缩略图。

## 数据流、错误处理与验证

PDF/文档队列的活动状态在 `App` 中派生；图片合成器只向上报告图片数和忙碌状态，不复制业务数据。页面 `<head>` 由当前工具和语言共同驱动，转换进度仍可临时覆盖标题。Canvas 根据自动图片质量模式声明频繁读回，消除浏览器性能警告。验证覆盖单元测试、类型检查、格式检查、生产构建，以及桌面/移动端的真实浏览器流程；部署后再检查线上 URL、标题、关键资源和控制台。
